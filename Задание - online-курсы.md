## **Описание**

Необходимо разработать backend для платформы онлайн-обучения.

Frontend разрабатывается отдельной командой и не входит в область проекта.

Все взаимодействие осуществляется через REST API.

---

# **Основные роли**

Система должна поддерживать три роли пользователей:

* Администратор  
* Преподаватель  
* Студент

Все проверки доступа должны выполняться на стороне backend.

---

# **Пользователи**

Backend должен предоставлять API для:

* регистрации пользователя;  
* аутентификации;  
* выхода из системы;  
* просмотра собственного профиля;  
* изменения профиля;  
* смены пароля.

Администратор дополнительно может:

* просматривать список пользователей;  
* изменять роли;  
* блокировать пользователей.

---

# **Курсы**

Каждый курс содержит:

* название;  
* описание;  
* стоимость;  
* категорию;  
* автора;  
* статус (черновик / опубликован).

API должно позволять:

* создавать курс;  
* редактировать курс;  
* удалять курс;  
* получать список курсов;  
* получать информацию о конкретном курсе.

Изменять курс может только его автор или администратор.

---

# **Категории**

Поддерживается CRUD категорий.

Каждый курс относится к одной категории.

---

# **Уроки**

Каждый урок принадлежит курсу.

Поля:

* название;  
* текст;  
* порядковый номер;  
* файл с дополнительными материалами (необязательно).

API должно позволять:

* создавать урок;  
* изменять урок;  
* удалять урок;  
* получать список уроков курса.

---

# **Покупка курса**

Студент может приобрести опубликованный курс.

Backend должен:

* создать запись о покупке;  
* обратиться к внешней платёжной системе;  
* сохранить идентификатор операции;  
* вернуть frontend ссылку для оплаты.

После получения webhook:

* проверить подпись;  
* изменить статус покупки;  
* предоставить пользователю доступ к курсу.

---

# **Прохождение курса**

Студент может отмечать урок как завершённый.

Backend должен хранить прогресс прохождения.

После завершения всех уроков курс считается пройденным.

---

# **Сертификат**

После успешного завершения курса необходимо:

* сформировать PDF сертификат;  
* сохранить его;  
* предоставить API для скачивания.

Формирование сертификата должно выполняться через очередь.

---

# **Поиск и фильтрация**

API должно поддерживать:

* поиск по названию курса;  
* фильтрацию по категории;  
* фильтрацию по преподавателю;  
* сортировку по стоимости;  
* сортировку по дате создания.

---

# **Авторизация**

Использовать собственную реализацию API-аутентификации, разработанную в рамках курса.

Использование Laravel Breeze, Jetstream, Fortify и аналогичных стартовых пакетов запрещено.

---

# **Очереди**

Минимум две фоновые задачи:

* генерация сертификата;  
* отправка уведомления после успешной оплаты.

---

# **События**

Минимум четыре доменных события:

* UserRegistered  
* CoursePublished  
* CoursePurchased  
* CourseCompleted

Использовать механизм Events и Listeners Laravel.

---

# **API**

Все основные операции должны быть реализованы через REST API.

Использовать корректные HTTP-методы:

* GET  
* POST  
* PUT/PATCH  
* DELETE

Ответы должны возвращаться в формате JSON.

# **Валидация**

Все входящие данные должны проверяться через Form Request.

---

# **Права доступа**

Необходимо использовать Policies и/или Gates.

Например:

* студент не может создавать курсы;  
* преподаватель не может изменять чужие курсы;  
* только администратор может управлять пользователями.

---

# **Логирование**

Все исключения должны логироваться.

Дополнительно рекомендуется логировать:

* публикацию курса;  
* покупку курса;  
* получение webhook;  
* завершение курса.
